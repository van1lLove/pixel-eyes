# Общий каталог Pixel Eyes 1.3

В настройках плагина откройте "Свои глаза и каталог", выберите свой сохранённый набор и нажмите "Опубликовать свои глаза". Укажите название, описание и до восьми тегов. После подтверждения откроется готовая заявка на GitHub. Войдите в свой аккаунт и нажмите Submit new issue. Пока эта кнопка не нажата, заявка не отправлена. Для особенно больших рисунков плагин скопирует содержимое заявки: вставьте его в описание вручную.

Публикуются только данные рисунка. Telegram ID, сообщения, контакты, настройки плагина и токены в заявку не входят. В каталоге автором будет подтверждённый аккаунт GitHub отправителя. Перед отправкой убедитесь, что имеете право делиться рисунком.

## Как проходит проверка

1. Плагин проверяет JSON по закрытому списку полей и ограничивает объём 64 КБ.
2. GitHub Actions повторяет проверку тем же валидатором. Код, архивы, ссылки на внешние файлы, повтор ключей и неизвестные поля не принимаются. Проверяются сетки (до 32x32), палитра, кадры эмоций, размещение (до 12 глаз на холсте 128x64), конечные числа и диапазоны поведения. Сжатый пакет имеет лимит распаковки.
3. Владелец смотрит заявку. При одобрении ставит метку `approved-skin`.
4. Автоматика создаёт PR с двумя файлами: новым JSON и обновлённым index.json. ID набора генерируется из автора и номера заявки: существующий набор заменить нельзя. Совпадающие рисунки отклоняются.
5. Владелец проверяет результат в редакторе и объединяет PR. После этого набор появится в каталоге у пользователей. Несколько PR с правками index.json объединяйте последовательно, с обновлением веток.

Данные заявок не передаются в shell и не исполняются. Workflow работает только с кодом default branch и не скачивает вложения пользователя. Токен записи существует только в GitHub Actions, в плагине его нет. Техническая проверка ограничивает формат и ресурсы, но не заменяет просмотр рисунка: оскорбительные картинки, копии чужих работ и рекламу отклоняет владелец.

## Однократная настройка репозитория

- Workflow `skin-submissions.yml`, `community/process_submission.py` и `source/community.py` должны находиться в основной ветке.
- Issues и Actions должны быть включены. Создайте метку `approved-skin`.
- Settings → Actions → General → Workflow permissions: разрешите Actions создавать pull requests. Широкие права по умолчанию не нужны, права заданы отдельно для каждого job.
- Дайте первой тестовой заявке пройти весь путь до PR. Не публикуйте релиз до этой проверки. Если настройки запрещают автоматический PR, бот оставит в заявке ссылку на подготовленную ветку: создайте PR вручную. Каталог до merge остаётся прежним.

## Фильтры в плагине

В каталоге есть поиск по названию, описанию, автору и тегам, точный фильтр тега, порядок по названию или автору и переключатель "Только ещё не добавленные". Подключение каталога разрешает только относительные пути `skins/*.json` из репозитория; произвольные адреса из index.json не скачиваются. Для новых наборов проверяется SHA-256 нормализованного JSON.

Проверки на ПК: `python source/test/community_test.py` и, после сборки плагина, `python source/test/plugin_harness.py`.
